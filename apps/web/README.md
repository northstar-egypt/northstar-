# NorthStar web

Next.js 15 (App Router) frontend in TypeScript, styled with Tailwind. Responsive, and mobile
first on the screens a coach uses pitchside.

The eight screens in `docs/wireframes` were the starting point and are all built; the app has
grown past them (role homes, the explorer, team gaps, match tagging, the assistant, the story
screen). Every screen reads from and writes to the real API behind a real sign-in. The data is
synthetic, generated by `data/pipelines/synthetic`, never fixtures in this app.

## Layout

```
app/
  layout.tsx            root layout, wraps everything in AuthProvider
  page.tsx              landing page
  login/                sign in, and the demo role picker
  story/                "the ones we'd have let go", the late-bloomer story screen
  (app)/                every signed in screen, shares nav and the role redirect
    dashboard/          coach home: the squad, measuring day, what the models noticed
    scout/              scout home and shortlist
    me/                 player home: your journey, and who can see your record
    oversight/          federation home: what needs a decision, map of Egypt
    players/new/        add a player, log a measurement
    players/import/     import players from a spreadsheet, preview first
    players/[id]/       player profile; report/ is the pro scouting report
    search/             scout search
    compare/            comparison, with radar overlay
    explore/            scatter explorer and position leaders
    gaps/               team gap analysis, club and national team
    matches/tag/        tag match events from video
    results/import/     import table tennis results from a spreadsheet
    ask/                the assistant
    integrity/          integrity board
components/
  ui.tsx                buttons, cards, chips, tables, banners
  charts.tsx            sparkline, growth curve, percentile bar, radar, bars, stacks
  egypt-map.tsx         governorate map (data in egypt-map-data.ts)
  pitch.tsx             pitch graphic for shot maps and the scouting report
  nav.tsx               top navigation and the development demo-account switcher
  api-status.tsx        connectivity indicator
lib/
  api.ts                every call to the API
  types.ts              response shapes, mirroring apps/api/app/schemas
  roles.ts              each role's accent colour and words
  auth.tsx              session state, NOT authentication
  format.ts             small formatting helpers
```

## Two deliberate absences

**No component library.** `components/ui.tsx` covers what these screens need. Adding one is a
new core dependency, which `CLAUDE.md` says to ask about first.

**No chart library.** The charts in `components/charts.tsx` are hand-written SVG with no
dependencies. Every chart follows the project's rule: when a value is not known (too little
history for a forecast, too few players for a percentile), it draws nothing and says why.

## Authentication

The login form calls `POST /auth/login`. The API sets an HttpOnly session cookie, which this
app never sees: `lib/api.ts` sends every request with `credentials: "include"` and the browser
attaches it. `lib/auth.tsx` asks `/me` who the session belongs to. Nothing about the session is
kept in localStorage, where a script could read it. The design is in `docs/threat-model.md`.

The rule the whole app follows: **role is a hint for what to render, never the enforcement
boundary.** If the API sends a field the current role should not see, hiding it in the browser
has not protected anything. Access control is in the API (`apps/api/app/services/access.py`).

In development the login screen lists one synthetic demo account per role (password
`northstar-demo`), and the top bar has a switcher. Both sign in for real through the same
endpoint; they only save typing. Outside development the API does not list demo accounts and
neither appears.

## Run with Docker (recommended)

From the repo root:

```bash
docker compose -f docker/docker-compose.yml up --build
```

Open http://localhost:3000. You land on the login page. Pick a demo role.

## Run without Docker

Needs Node 20+. From `apps/web`:

```bash
npm install
npm run dev
```

The app expects the API at `http://localhost:8000`. Override with `NEXT_PUBLIC_API_URL`.
Without the API the screens load but have no data, and the connectivity indicator in the
footer shows red.

## Checks

```bash
npx tsc --noEmit
npm run build
```

CI runs both, plus `npm run lint -- --max-warnings 0`. There are no unit tests in this app;
the screens are covered by the Firefox end-to-end tests below. Unit tests for
`components/charts.tsx` (empty data, the forecast band, a cohort too small to show) would be
the most useful first ones.

## Notes

- This package is part of the repo-root npm workspaces.
- `apps/web/lib/` needs an explicit exception in the root `.gitignore`, because the Python
  section ignores any directory called `lib`. Do not remove it.

## End-to-end tests

The browser tests live in `tests/e2e` at the repository root, because they drive this app, the
API and PostgreSQL together. They run in **Firefox**, which is the browser the team uses, via
Playwright. See `tests/e2e/README.md` for what has to be running first.

```bash
python -m playwright install firefox   # once
pytest tests/e2e
```
