Annotations

  1. The language box is the front door, filters are the back one. A scout thinks in sentences, not in field names. But natural language alone is unpredictable, so the filters stay visible and stay authoritative. Neither is hidden behind a tab.
  2. The interpretation strip is the most important element on this screen. It shows what the sentence was turned into, as editable chips. Without it the scout cannot tell a real absence of results from a misread query. Note the last chip: the system says plainly that it has no data on footedness rather than quietly dropping that part of the request.
  3. A match percentage needs a stated basis or it should be a rank instead. If this number comes from embedding similarity, it is a similarity score and should say so on hover. A bare percentage invites a scout to read precision that is not there.
  4. Consent gating shown as a locked card, not a silent omission. This is one of two possible answers to the open question on the index page, drawn here so the team can react to something concrete. The argument for it: a scout who cannot see a player still learns that a matching player exists, and there is a legitimate route to ask. The argument against: that is itself a disclosure about a minor. The team has to choose, and the alternative is that this card simply does not appear.

Data and API

  • The sentence goes to the API, which turns it into filters plus an embedding similarity query. The parsing happens server side so the frontend never needs to know how it works.
  • Structured filters map to Player columns and to derived values the ML layer has written back, such as percentile positions and flags.
  • Similarity ranking depends on the embedding store, which the ML track has explicitly deferred until they pick a model. Until then this screen can ship on filters alone, with the language box disabled and labelled as coming.
  • Results must be filtered for consent and role inside the API. A withheld player must arrive at the frontend already stripped of the fields the scout may not see, not merely marked as hidden.
  • Each search writes search.run to AuditLog, with the query. That record is what makes it possible to notice a scout systematically probing minors' records.

Open questions

  • Does a saved search notify the scout when a new player matches it? That is a genuinely useful feature and a genuinely uncomfortable one when the subjects are children. Worth a deliberate decision rather than drifting into it.
  • Table tennis results in the same list as football. The card shows height and goals per 90, which mean nothing for a table tennis player. Either the card is sport aware, or search is scoped to one sport at a time. The second is simpler and probably right.
  • What is the default scope for a scout with no filters set? Everything they are allowed to see is a lot of rows and not a useful starting point.
