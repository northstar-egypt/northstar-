Annotations

  1. Minor status is computed and announced, not asked. The coach enters a date of birth and the interface immediately says what that means, in the same place, before they can move on. Nobody should be able to add a 13 year old without being told that consent is now required. This is the privacy rule made visible rather than buried in a policy page.
  2. Egypt eligibility is a first class toggle, because the diaspora tier is a headline feature and the flag is otherwise invisible data entry. A coach at an Egyptian academy will rarely touch it. A scout logging a dual national in Europe will use it constantly.
  3. The date defaults to today and is one tap to change. Almost every measurement is logged the day it is taken. Making the common case free is worth more here than anywhere else in the app.
  4. Validation is a question, never a block. The number is implausible, so the interface says so and offers a correction. It does not refuse to save. A coach who genuinely measured a 12 cm jump must be able to record it, because that is exactly the observation the late bloomer detector needs. What the interface must never do is let it through silently.
  5. The primary action is thumb sized and at the bottom, where a thumb actually reaches on a phone held one handed. Numeric fields open a numeric keypad, and the value is set in a larger type size than anything else on screen so it can be checked at arm's length in bright sun.

Data and API

  • Step 1 creates a Player and the PlayerOrganization row that links them to the coach's org. Those are one transaction, because a player with no affiliation is invisible to every screen in this product.
  • Step 2, not drawn, is consent capture when the player is a minor. It writes Consent rows per purpose.
  • Logging writes one Measurement row per metric, long format, with source set to coach_logged and recorded_by set to the signed in user.
  • confidence is on the model as measured or estimated but is not on this form yet. The maturity models care about it, so it probably belongs here as a quiet toggle.
  • Every write appends to AuditLog, including the case where the coach saved a value the interface questioned. That before and after context is exactly what the integrity board reads later.

Open questions

The offline claim

The wireframe promises an offline save. That is the right behaviour for a pitchside tool and the wrong thing to promise casually: it means a service worker, a local queue, conflict handling on sync, and a story for what happens when the same measurement is entered twice from two devices. Either the application track commits to building it, or the line comes off the screen. Drawing it and not building it is the worst of the three options.

  • Which metrics beyond height and weight go on the quick form? The schema allows any metric, but a form with twenty fields will not get used pitchside.
  • Does the position chip set come from the sport module or a hard coded list? The schema flags position as a borderline field, so this screen inherits that open question.
  • Consent capture is drawn as step 2 but not designed. Who signs, on what device, and does a guardian signature need to be a stored document.
