Desktop only. This is a sit down and read screen, used at a desk.

Annotations

  1. Staleness is the headline number, not player count. A federation can grow the player count by onboarding one large academy and learn nothing. The share of records that have gone stale is the number that says whether the database can be trusted, so it is promoted to the top row.
  2. Coverage against population, not raw totals. Cairo will always have the most tracked players. The interesting fact is a governorate with two million people and eleven tracked players, and only a normalised view surfaces that. This is the screen where the national mission is either visible or it is not.
  3. The academy table is sorted by the worst first, deliberately. A federation officer opens this to find who needs a phone call. Sorting by size would put the well run academies at the top and bury the problem.
  4. The diaspora watchlist earns its own block because tracking Egypt eligible players abroad is a stated reason the project exists and nobody currently does it. Everywhere else in the product diaspora players are just search results. Here they are a list somebody is responsible for.

Data and API

  • Nearly all aggregates, computed server side. This screen should never pull player rows to count them in the browser.
  • Organization with counts and recency derived from PlayerOrganization and Measurement.
  • Consent completeness per academy comes from Consent, and is a genuinely useful lever: it is the number that gets an academy to chase signatures.
  • The governorate view needs a location on Organization. The schema has country only. Either a region column is added, or this panel cannot be built as drawn. Worth raising with the data track early because it is a small migration if caught now.
  • Export writes an AuditLog entry. A national data export is exactly the action that should leave a trace.

Open questions

A missing column

Coverage by governorate is drawn here because it is the most compelling thing this screen can show, and the schema cannot currently produce it. Organization stores an ISO country code and nothing finer. This is the clearest example of wireframing paying for itself: the gap surfaced before anyone wrote the endpoint. Adding a region field is cheap now and awkward once there is data.

  • What can a federation user do here, or is it read only? Read only is the safer default and matches the role intent in the schema, but then "oversight" means observation without a lever.
  • Should an academy be able to see its own row and how it compares? Transparency helps, and a public league table of academies is a political object the federation may not want.
  • Export format and scope. A national export of minors' data is the highest risk action in the entire product and should probably be restricted well beyond the federation role.
